# Изменения

Формат: одна секция на версию, сверху — свежая. Версия репозитория хранится в файле `VERSION`;
её изменение в ветке `main` автоматически создаёт тег и релиз.

## 1.3.1 — 2026-09-22

- `close` объясняет отказ Redmine по полям, которых больше нет в проекте (удалённая категория или
  версия блокируют сохранение задачи целиком), и умеет сбросить их при закрытии — флаг
  `--clear-invalid`. Найдено на реальной задаче с оценкой 250 часов.

## 1.3.0 — 2026-09-22

- **Разбор зависших задач** (`stale`): сводка по категориям и проектам, разбор пачками по десять с
  готовностью, списанным временем, сроком молчания и описанием. Категории различаются по смыслу:
  завершённые без закрытия, отложенные и брошенные без движения.
- **Массовое закрытие** (`close`): общий комментарий обязателен, задачи закрытых проектов
  пропускаются отдельным списком, а не падают с ошибкой.
- Задачи закрытых и архивированных проектов больше не засоряют выдачу `issues`: они доступны только
  для чтения, изменить их всё равно нельзя. Показать — `--include-closed-projects`.

## 1.2.3 — 2026-09-22

- Общий модуль проверки текста ловит реквизиты, записанные в таблице (колонка «Пароль», значение
  строкой ниже), и больше не принимает за них размеры изображений, даты, версии и диапазоны.

## 1.2.2 — 2026-09-22

- Правило про пароли и ключи различает реквизит и указание, где его взять: «Ключ доступа: Моя учётная
  запись → Ключ доступа к API» больше не блокирует отправку, а «пароль Zx9!kLm2025» — блокирует,
  в том числе без двоеточия после слова.
- Модуль проверки текстов стал общим со скиллом outline-docs: правила для задач и для базы знаний одни.

## 1.2.1 — 2026-09-22

- Список внутренних доменов вынесен из кода в настройку (`AUDIT_INTERNAL_DOMAINS` или
  `audit.internalDomains` в конфиге): сканер больше не раскрывает адреса организации самим фактом
  своего содержимого. В CI значения приходят из секретов репозитория.
- Аудит истории проверяет каждую версию файла во всех ветках и тегах, а не только строки из диффов,
  и применяет к истории правила про внутренние адреса. Находка адресуется файлом, версией и строкой.
- Файлы без расширения (`VERSION`, `LICENSE`) больше не считаются бинарными и тоже проверяются.

## 1.2.0 — 2026-09-22

Работа, сделанная в репозитории, превращается в задачи и списания; скилл обновляет себя сам.

- **Сбор по истории git** (`harvest`): коммиты за период группируются в рабочие сессии, часы считаются по
  времени сессий, коммиты с `#NNNN` относятся к существующим задачам (наличие проверяется в Redmine),
  остальное предлагается завести как новые задачи с черновиком описания. `--out` сохраняет `entries.json`
  для `batch`, `plan.json` и тексты описаний.
- **Привязка репозиториев** (`repos add|list|remove`): репозиторий → инстанс, проект и организация-клиент.
- **Автообновление** (`scripts/update.ts`): перемотка вперёд из репозитория, не чаще раза в сутки,
  с отказом при несохранённых локальных изменениях. Ставится hook-ом на старт сессии.
- **Проверки в CI**: типы, самопроверка (69 случаев) и аудит репозитория вместе с историей на каждый push.
- **Автоматический релиз**: изменение файла `VERSION` в `main` создаёт тег и запись в Releases с архивом
  скилла и собранной инструкцией в PDF.
- `scripts/audit-repo.ts`: сканер утечек по файлам под контролем версий и по всей истории коммитов.
- Исправлено: разбор `--numstat` в истории git, распознавание заглушек вида `"…"` и «ваш ключ»,
  правило для ключей в шестнадцатеричном виде рядом со словами «ключ», «токен», «secret».

## 1.1.0 — 2026-09-22

Скилл получил роль аналитика: он не просто передаёт текст в Redmine, а оформляет его и проверяет.

- **Редакционный стандарт** (`references/editorial.md`): структура описаний и комментариев, шаблон шапки
  родительской задачи, правила декомпозиции, таблица переформулировок.
- **Проверка перед отправкой** (`scripts/guard.ts`): учётные данные, токены, приватные ключи, строки
  подключения, платёжные и персональные данные — запрет; внутренние адреса, самооговор, оценки людей,
  обещания без условий, внутренняя экономика — запрет в клиентских задачах. Режим аудитории `--audience`.
- **Подтверждение записи**: команды, изменяющие Redmine, без `--yes` печатают полный предпросмотр и выходят.
- **Деревья задач**: `create-tree` создаёт родителя с подзадачами одной операцией, `tree` показывает
  агрегаты оценок, списанного времени и взвешенной готовности.
- **Разметка инстанса**: `detect-markup` определяет textile/markdown/html, профиль хранит выбор в `markup`.
- `update-issue` принимает описание, тему, родителя и оценку; предпросмотр разворачивает идентификаторы в названия.
- Исправлено: границы слов для кириллицы в правилах проверки (`\b` в JavaScript их не распознаёт),
  разбор строк подключения с `@` в пароле, распознавание заглушек вида «см. хранилище».
- `scripts/selftest.ts`: 55 проверок разбора ввода и правил без обращения к Redmine.
- `scripts/update.ts`: обновление скилла перемоткой вперёд с защитой локальных изменений.

## 1.0.0 — 2026-09-22

Первый выпуск.

- Списание трудозатрат: одиночное, пачкой из JSON, правка и удаление записи.
- Отчёты по периодам с группировкой по задачам, дням, проектам и видам деятельности; контроль недобора часов.
- Сводка новых событий: назначения, комментарии, изменения полей, с отметкой «просмотрено».
- Контроль сроков с разбивкой на просроченное, сегодняшнее и ближайший горизонт.
- Работа с задачами: карточка с историей, поиск, фильтры, создание, комментарии, смена статуса и готовности.
- Несколько инстансов Redmine в одном конфиге, кэш справочников, единый разбор ошибок API.
