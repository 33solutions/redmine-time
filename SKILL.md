# Redmine: трудозатраты, задачи, входящие

Всё делается одним CLI на Bun. Инстансов два — `company` (redmine.example.com) и `ru` (redmine.example.com).

```bash
bun ~/.claude/skills/redmine-time/scripts/redmine.ts <команда> [флаги]
```

Первым делом в незнакомой ситуации: `... help` — полный список команд и флагов.

## Настройка (один раз)

Конфиг: `~/.redmine/config.json`. Образец — `config.example.json` в папке скилла.
API-ключ берётся в Redmine: *Моя страница → Моя учётная запись → Ключ доступа к API*.
Ключ вписывает пользователь сам — не проси продиктовать его в чат и не вставляй его в команды.

Проверка: `... instances`, затем `... whoami --instance company` и `... whoami --instance ru`.
Переменные `REDMINE_URL` / `REDMINE_API_KEY` / `REDMINE_INSTANCE` переопределяют конфиг.

## Выбор инстанса

- Явно сказан («в ru», «на .company») → `--instance ru|company`.
- Не сказан → берётся `default` из конфига. Если задача упоминается по номеру, а номер не находится в дефолтном инстансе — проверь второй, прежде чем сообщать «задача не найдена».
- Для сводок `inbox` и `due` предпочитай `--all-instances`: пользователь думает про свою работу целиком, а не про то, где заведена задача.

## Правила записи (обязательно)

1. **Подтверждение перед записью.** Перед `log`, `batch`, `edit`, `delete`, `update-issue` покажи, что именно будет записано — дата, задача, часы, вид деятельности, комментарий, инстанс — и дождись явного «да». Для показа используй `--dry-run`: он выполняет все проверки и резолв справочников, но ничего не пишет.
2. Один вызов = одна операция. Пачку записей делай через `batch`, а не циклом из отдельных `log` — так предпросмотр честно покажет итоговую сумму часов.
3. Комментарий к записи пиши по делу и по-русски: что сделано, а не «работа по задаче». Если пользователь не дал формулировку — предложи свою и подтверди её вместе с остальным.
4. `delete` необратим: он требует `--yes` и отдельного подтверждения пользователя, даже если тот только что разрешил другую запись.
5. Часы считай честно. Если пользователь сказал «весь день» — уточни норму (обычно 8) вместо того, чтобы придумывать число.

## Частые сценарии

**Списать часы**
```bash
bun ~/.claude/skills/redmine-time/scripts/redmine.ts log --issue 1234 --hours 2.5 --comment "Рефакторинг ws-роутера" --dry-run
bun ~/.claude/skills/redmine-time/scripts/redmine.ts log --issue 1234 --hours 2.5 --comment "Рефакторинг ws-роутера"
```
Часы: `2` · `2.5` · `1h30` · `1:30` · `90m`. Даты: `today` · `yesterday` · `-3` · `2026-09-18` · `18.09`.
Без `--issue` списывается на проект: `--project <identifier|часть названия>`.

**Отразить несколько дней сразу** — собери JSON и покажи предпросмотр:
```bash
cat > /tmp/entries.json <<'EOF'
[
  {"issue": 1234, "hours": "3", "date": "2026-09-18", "comment": "Протокол wss: схемы сообщений"},
  {"issue": 1237, "hours": "1h30", "date": "2026-09-18", "comment": "Ревью PR"}
]
EOF
bun ~/.claude/skills/redmine-time/scripts/redmine.ts batch --file /tmp/entries.json --dry-run
```

**Что нового / что на мне**
```bash
... inbox --all-instances                 # с прошлой отметки (по умолчанию — за 7 дней)
... inbox --since -3 --all-instances      # за последние 3 дня
... inbox --all-instances --mark          # и запомнить «просмотрено»
```
`inbox` показывает: новые задачи на мне, назначения на меня, новые комментарии и изменения полей — чужие; свои действия добавляются флагом `--include-own`. `--watched` добавляет задачи, за которыми слежу, `--authored` — мои собственные.
Отметка «просмотрено» хранится в `~/.redmine/state.json` по инстансу. Ставь `--mark` только когда пользователь действительно ознакомился со сводкой.

**Сроки**
```bash
... due --all-instances            # секции: просрочено / сегодня / ближайшие 14 дней
... due --days 3 --all-instances
... due --all --all-instances      # вообще все открытые на мне, включая бессрочные
```
Просроченные больше чем на 90 дней по умолчанию скрыты (это обычно незакрытые хвосты, а не работа) — их число выводится в конце, показать полностью можно флагом `--stale`, а порог сдвинуть `--stale-days N`.
Если в выдаче много задач в статусах вроде «Принята» или «Выполнена» с готовностью 100% — это незакрытые хвосты; предложи пользователю `--exclude-status "Принята,Выполнена"` вместо того, чтобы пересказывать их все.

**Отчёт по списанному**
```bash
... entries --period week --group issue      # неделя в разрезе задач
... entries --period last-month --group date
... entries --period 2026-09 --group project
... gaps --period week                       # дни, где не добрано до нормы
```
`--user all` — по всем (нужны права), `--user <id>` — за конкретного человека.

**Задачи**
```bash
... issue 1234                 # карточка + последние события
... issues --mine --limit 20   # открытые на мне
... search "ws-протокол"
... update-issue 1234 --done 60 --note "Готово ядро, остался клиент" --dry-run
... comment 1234 --text "Готово, жду проверки"
... create-issue --project core --subject "Тема" --description-file /tmp/d.md --due +7 --dry-run
```
Длинное описание передавай через `--description-file`, а не `--description`: так не ломаются переносы строк и кавычки. Разметка — textile (`h2.`, `*` для списка, `@код@`) либо HTML, в зависимости от настроек инстанса; посмотри соседнюю задачу через `issue <id>`, если не уверен.
Справочники для создания: `... trackers` (трекеры и приоритеты), `... statuses`, `... activities`.

## Как отвечать пользователю

- Не пересказывай таблицу CLI целиком — выдели суть: сколько списано, где недобор, что просрочено, что требует ответа.
- По задачам всегда давай номер и ссылку: CLI печатает URL нужного инстанса.
- Когда инстансов два, помечай, откуда задача, если это не очевидно из контекста.
- `--json` используй, когда нужно самому посчитать или сверить данные; человеку показывай текстовый вывод.

## Диагностика

- `401` — ключ неверный/просрочен: пусть пользователь перевыпустит его в профиле Redmine.
- `403` — прав не хватает у владельца ключа (частый случай: списание часов за другого пользователя, закрытый проект).
- `404` на всех запросах — в Redmine выключен REST API: *Администрирование → Настройки → API → Включить веб-сервис REST*.
- `422` — валидация: чаще всего не задан обязательный вид деятельности (`--activity`, см. `... activities`) или дата вне допустимого периода.
- Справочники (виды деятельности, статусы, проекты) кэшируются на сутки в `~/.redmine/cache.json`; после изменений в Redmine добавь `--no-cache`.
