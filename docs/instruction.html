redmine-time · инструкция для команды

Redmine прямо из чата

Скилл redmine-time для Claude Code: списывайте трудозатраты, узнавайте о новых задачах и комментариях, держите сроки под контролем, связывайте задачи, ведите проекты, их участников и wiki — обычными фразами, не открывая браузер.

Версия 1.9.0 Обновлено 23.09.2026 Репозиторий github.com/33solutions/redmine-time Время установки ≈ 10 минут

1Зачем это нужно

Учёт времени отнимает время. Чтобы списать два часа, нужно открыть Redmine, найти задачу, выбрать вид деятельности, заполнить форму — и так по каждой задаче в конце дня. Скилл убирает этот путь: вы пишете в чат Claude Code одну фразу, подтверждаете предпросмотр — запись уходит в Redmine.

Так же работает и обратное направление: вместо того чтобы просматривать почту и списки задач, вы спрашиваете «что у меня нового» и получаете сводку — новые задачи на вас, чужие комментарии, изменения статусов и горящие сроки. Сразу по всем подключённым инстансам.

Третье направление — порядок в самом Redmine: связи между задачами, проекты и подпроекты, участники и их роли, wiki проекта. Здесь скилл не только оформляет запись, но и объясняет последствие словами: что станет нельзя сделать после связи или закрытия проекта, что откроется человеку с этой ролью, кто прочитает страницу wiki.

3Настройка за три шага

Шаг 1. Получите ключ доступа к API

Откройте Redmine → Моя учётная запись → справа блок Ключ доступа к API → Показать. Ключ — это ваш личный пароль к API: он даёт ровно те права, что есть у вашей учётной записи, и никому его передавать не нужно.

Например: redmine.example.com/my/account и redmine.another.example/my/account.

Шаг 2. Создайте файл конфигурации

mkdir -p ~/.redmine
cp ~/.claude/skills/redmine-time/config.example.json ~/.redmine/config.json

Откройте ~/.redmine/config.json и впишите ключи:

{
  "default": "work",
  "instances": {
    "work": {
      "url": "https://redmine.example.com/",
      "apiKey": "ваш ключ",
      "defaultActivity": "Разработка",
      "dailyTargetHours": 8
    },
    "second": {
      "url": "https://redmine.another.example/",
      "apiKey": "ваш ключ",
      "dailyTargetHours": 8
    }
  }
}
ПараметрЧто задаёт
defaultинстанс по умолчанию, когда вы не уточняете, где задача
defaultActivityвид деятельности, если не назвали его явно
dailyTargetHoursдневная норма для отчёта о недоборе часов
projectAliasesкороткие имена проектов на свой вкус: "ядро" → "core-platform"

Шаг 3. Проверьте связь

bun ~/.claude/skills/redmine-time/scripts/redmine.ts whoami
bun ~/.claude/skills/redmine-time/scripts/redmine.ts whoami --instance second

Первая команда проверяет инстанс по умолчанию, вторая — второй. Ответ вида «Пользователь: Иван Иванов (i.ivanov, id=42)» по каждому инстансу означает, что всё готово.

Ключ не попадёт в чужие руки: он хранится только на вашем компьютере в ~/.redmine/config.json, не печатается в выводе и исключён из репозитория через .gitignore.

Перед каждой записью — предпросмотр. Скилл обязан показать, что именно уйдёт в Redmine: дату, задачу, часы, вид деятельности, комментарий и инстанс. Пока вы не подтвердили — в Redmine ничего не меняется. Удаление требует отдельного подтверждения.

5Как скилл пишет тексты

Вы даёте суть — скилл оформляет документ. Описание задачи собирается по фиксированной структуре, чтобы её можно было принять, не задавая вопросов:

  • Что делаем — результат одним абзацем, без пересказа переписки.
  • Зачем — что изменится у заказчика.
  • Объём работ — нумерованный список этапов.
  • Критерии приёмки — проверяемые утверждения, а не «должно работать».
  • Ограничения и допущения, Требуется от заказчика (кто, что, к какой дате), Связи с номерами задач.

Комментарий строится как отчёт о шаге: сделано (с числами) → как проверить → что это даёт → дальше → что требуется от вас с датой. Формулировки проходят редактуру: вместо «мы накосячили, обмен упал» — «обмен останавливался на заказах без артикула; добавлена проверка и повторная отправка, за сутки сбоев нет».

Разбор задачи на подзадачи

Скажите «разбери на подзадачи» — скилл предложит дерево: родительская задача с целью, составом работ и контрольными точками, и подзадачи по 2–16 часов, каждая со своими критериями приёмки и сроком. Оценка, списанное время и готовность родителя считаются по подзадачам автоматически, поэтому в шапке цифры не дублируются. Дерево показывается целиком до создания.

Тексты о сбоях и инцидентах

Текст про сбой, взлом, утечку или простой живёт дольше самого инцидента, и его читают не только участники задачи. Поэтому он пишется сухой хронологией: что обнаружено, что сделано, как проверено. Без распределения вины, без юридических обязанностей и без подробностей атаки. Утверждение о мире заменяется утверждением о наблюдении: не «данные не утекли», а «признаков доступа к данным не обнаружено» — второе остаётся верным, что бы ни выяснилось завтра.

6Связи между задачами

Подзадачи отвечают на вопрос «из чего состоит работа», связи — на вопрос «что от чего зависит». Скажите, какая задача ждёт какую, — скилл оформит связь в Redmine, и дальше Redmine следит за порядком сам: не даст закрыть заблокированную задачу раньше времени и сдвинет сроки следующего этапа, если перенесли предыдущий.

Перед созданием скилл проверяет, что обе задачи существуют и доступны вам, что это не одна и та же задача и что связи между ними ещё нет. Между двумя задачами бывает только одна связь: чтобы сменить её вид, прежнюю сначала удаляют — тоже с предпросмотром. Если Redmine откажет, например потому что связь замкнёт круг в порядке выполнения или свяжет задачу с её же подзадачей, вы увидите причину словами, а не код ошибки.

Какие связи уже есть, покажет фраза «какие связи у #25185?»: вид связи, номер, тема и статус второй задачи. Связи видны и в карточке задачи.

Связь — это поведение, а не пометка. Блокировка запрещает закрыть задачу, порядок выполнения двигает сроки, дубль закрывается вместе с оригиналом. Предпросмотр говорит об этом до вашего «да». Зависимость «ждём соседнюю задачу» лучше оформить связью, чем фразой в тексте: за связью Redmine следит сам.

Задачи на разных инстансах

Связь Redmine существует только внутри одного инстанса. У второго Redmine своя нумерация, и связать задачи двух баз нельзя ни в интерфейсе, ни через API. Скилл говорит об этом прямо и не пытается это обойти.

Вместо связи ставится перекрёстная ссылка в тексте обеих задач. Попросите «дай ссылку на #25185 для второго инстанса» — скилл напечатает готовую строку в разметке того инстанса, куда она пойдёт: полный адрес, название проекта и тема. Если инстансов подключено больше двух, назовите, куда пойдёт ссылка: от этого зависит разметка. Вставляется строка обычным путём — комментарием или правкой описания, с предпросмотром.

<a href="https://redmine.example.com/issues/25185">Пример: сопровождение #25185 — Обмен с сайтом</a>
  • Номер без адреса на другом инстансе — ошибка. Там #25185 указывает на чужую задачу, и ссылка ведёт не туда. Задачу своего инстанса пишут номером, задачу другого — только полным адресом с названием проекта.
  • Ссылка нужна с обеих сторон. Задача на разработку называет задачу внедрения у клиента, задача внедрения — задачу на разработку. Односторонняя ссылка находится только тем, кто и так знает, где искать.
  • Такие ссылки скилл находит в описании и комментариях и показывает в карточке задачи отдельным блоком «Связано на другом инстансе», чтобы единственная связь не терялась в тексте.

7Проекты и подпроекты

Проект — контейнер работы: у него свои участники, трекеры, модули и отчётность. Скилл показывает проекты деревом «родитель → подпроекты», заводит новые и меняет настройки существующих — с тем же предпросмотром, что и у задач.

Проект или подпроект

Отдельный проект нужен, когда у работы свой заказчик, свой договор и своя отчётность. Направление внутри действующего клиента — подпроект: так отчёты по клиенту собираются целиком, а участников можно унаследовать от родителя. Не уверены, куда встраиваться, — попросите «покажи проекты деревом».

Проект создан. Дерево проектов — с новым подпроектом на своём месте.
  • Идентификатор — короткое латинское имя в адресе проекта — собирается из названия: «Пример: маркетплейсы» → primer-marketpleysy. До создания скилл проверяет, что он свободен, в том числе среди закрытых и архивных проектов.
  • Описание — документ, а не строка. Что это за работа, где её границы (что ведётся здесь, а что в соседних проектах) и как здесь ведут задачи. Сроков, фамилий и номеров версий в описании проекта нет: они устаревают раньше, чем его перечитают. Нет в нём и сумм договора — это внутренняя экономика.
  • Трекеры и модули выбираются из того, что есть на инстансе. Несуществующее название останавливает создание и показывает список доступного.
  • Обязательные поля. Если на инстансе у проектов есть обязательные поля, скилл покажет их и допустимые значения («какие поля есть у проектов?»), отметит незаполненные в предпросмотре, а отказ Redmine по такому полю объяснит: какое поле и чем его заполнить.
  • Правка — название, описание, родитель, доступ, трекеры, модули и поля: «переименуй проект…», «вынеси подпроект на верхний уровень». Предпросмотр показывает каждое изменение как «было → станет».
Новый проект создаётся закрытым — его видят только участники. Публичный проект виден всем, у кого есть учётная запись в Redmine; для клиентской работы это почти всегда ошибка, и скилл предупредит о ней до подтверждения. Состав нового проекта зависит от того, кто его создал: если не администратор, создатель уже в нём — с ролью, которую Redmine назначает создателю проекта; у проекта, созданного администратором, участников нет, если их не унаследовали от родителя. Остальных добавьте сразу после создания и проверьте состав фразой «кто у нас в проекте?» — раздел 8.

Создать проект может администратор Redmine или роль с правом «Создание проекта», подпроект — роль с правом «Создание подпроектов» в родительском проекте. Архивировать проект может только администратор Redmine: скилл скажет об этом заранее, а не после отказа.

Закрыть проект

Работа по проекту закончена — проект закрывают. Закрытый проект остаётся на виду: задачи, wiki, документы и файлы читаются, но ничего не меняется. Это не архив: архив скрывает проект целиком и доступен только администратору, а закрыть проект может менеджер.

  • Закрывается всё дерево. Redmine закрывает проект вместе со всеми его подпроектами — и теми, что вам не видны, и теми, где у вас нет роли. Предпросмотр перечисляет видимые: убедитесь, что закрыть надо их все.
  • Открыть обратно — «открой проект обратно». Redmine откроет и все закрытые подпроекты под ним, в том числе закрытые отдельно раньше; скилл предупредит об этом заранее. Если какой-то подпроект должен остаться закрытым, закройте его снова.
  • Время в закрытом проекте не списывается. Если часы ещё не отражены, спишите их до закрытия.
  • Писем при закрытии Redmine не рассылает — заказчик узнает о закрытии, только если ему сказать.

Закрыть и открыть проект может роль с правом «Закрывать / открывать проекты» — обычно «Менеджер» — или администратор Redmine. Скилл заранее скажет, есть ли это право у вас. Через скилл закрытие работает на Redmine 5.0 и новее; на старом инстансе скилл ничего не изменит и подскажет кнопку: страница проекта «Обзор» → «Сделать закрытым».

Участник проекта — это доступ и почта, а не строка в списке: он видит задачи в объёме своей роли и получает по ним уведомления. Добавить человека в клиентский проект — значит открыть ему переписку с заказчиком. Поэтому решение всегда за вами, а предпросмотр объясняет, что именно откроется.

Человека, который не состоит ни в одном видимом вам проекте, по имени не найти (если у вас не администраторская учётная запись): понадобится номер из его профиля в Redmine.
  • Группа — тоже участник. Группу добавляют в проект так же, как человека, но роль получает каждый её участник, в том числе будущий: кого потом добавят в группу, тот сразу получит доступ к проекту. Предпросмотр говорит об этом отдельно.
  • Роль объясняется словами. Название роли постороннему ничего не говорит, а «видит все задачи, кроме приватных, и только свои списания» — говорит. Проверьте, что роль открывает ровно то, что человеку положено видеть.
  • Смена ролей задаёт набор целиком: роль, которую не назвали, снимается. Роли, унаследованные от группы или родительского проекта, этой операцией не меняются — их меняют там, откуда они пришли. Если вы снимаете с себя последнюю роль с правом управлять участниками, скилл предупредит: вернуть её себе сами вы не сможете.
  • Уже участник второй раз не добавляется. Скилл назовёт его текущие роли и предложит их сменить.
  • Удаление — отдельное подтверждение, даже если вы только что согласились на другую операцию. Списанные часы, комментарии и авторство задач остаются; открытые задачи на человеке лучше переназначить — предпросмотр покажет, сколько их.
  • Унаследованную роль здесь не снять. Если роль пришла от группы или родительского проекта, убрать человека можно только там, откуда она пришла: из группы или из наследования участников в настройках проекта. Скилл скажет об этом до отправки; если у человека есть и собственные роли в этом проекте, их можно сократить сменой ролей.
После записи скилл перечитывает состав. Redmine иногда молча пропускает роли, которые вам не разрешено назначать, и всё равно отвечает «успешно». Такое расхождение скилл покажет словом «РАСХОЖДЕНИЕ» с причиной: эту роль назначает администратор или менеджер проекта.

Менять состав участников может роль с правом «Управление участниками» в этом проекте. Если права нет, скилл скажет, какого именно не хватает и кто его выдаёт.

10Зависшие задачи и прошлые периоды

Разбор зависших задач

Задачи копятся годами: часть сделана, но не закрыта, часть отложена «до выяснения», часть заведена и забыта. Скажите «разбери зависшие задачи» — скилл покажет сводку по проектам, а затем пачки по десять: готовность, списанное время, сколько месяцев без движения и описание, с оценкой «закрыть или оставить» по каждой. Решение по каждой задаче — ваше.

Закрыть можно пачкой, но только с общим комментарием: читатель должен понимать, почему задача закрыта. Смена статуса рассылает письма участникам, в клиентских проектах — и заказчику; скилл предупредит об этом до начала. Если рабочий процесс не разрешает закрыть задачу, скилл скажет об этом прямо и перечислит доступные закрывающие статусы.

Заполнить прошлое

Работу, которая шла мимо трекера, можно восстановить постфактум. Скилл покажет, где дыры, — задачи без списаний, месяцы без часов, дни с неправдоподобной нагрузкой, — и поможет закрыть их по готовым отчётам или по истории git (раздел 13).

  • Даты начала и срока задачи ставятся по реальному периоду работы. Дату создания Redmine всегда ставит сегодняшнюю, поэтому реальный период читается по датам начала, срока и списаний.
  • Часы разносятся по дням, а не одной записью на дату закрытия: 27 часов в одной клетке читаются как отметка, те же часы по пяти дням — как работа. День длиннее 12 часов и дата в будущем вызывают предупреждение.
  • После отправки пачки скилл сверяет сумму по каждой задаче «было → стало».

11Что проверяется перед отправкой

Мы работаем с задачами, которые видит заказчик. Поэтому каждый текст — описание, комментарий, страница wiki, даже комментарий к списанию часов — проходит автоматическую проверку.

Не уходит никогдапароли и ключи, токены и приватные ключи, строки подключения с учётными данными, номера карт, СНИЛС и паспортные данные
Не уходит заказчикувнутренние IP и имена серверов, признание вины, оценки людей и чужой работы, обещания без условий, себестоимость и ставки, упоминание других клиентов, а в текстах об инцидентах — юридические обязанности, распределение вины и подробности атаки
Показывается на решениелокальные пути, телефоны, адреса почты, ИНН

Находка первой категории останавливает отправку: текст нужно исправить. Если реквизит доступа всё же был опубликован — правки комментария недостаточно, Redmine хранит историю изменений, и ключ нужно отзывать.

13Сделанное по истории git

Если работа шла в репозитории, скилл соберёт отчёт сам: привяжите репозиторий к проекту Redmine — и коммиты за период превратятся в черновик того, что можно списать и какие задачи завести.

bun $R repos add --path . --instance work --project core --client "Клиент" --activity "Программирование"
bun $R harvest --repo . --period week --out /tmp/harvest

Коммиты группируются в рабочие сессии: подряд идущие коммиты — один заход, разрыв больше полутора часов — новый. Коммиты с номером задачи (#25127) относятся к ней, остальное предлагается завести как новые задачи с черновиком описания.

Оценка часов — черновик, а не факт. Она считается по времени между коммитами и нужна, чтобы не вспоминать день по памяти. Проверьте цифры и тексты перед отправкой: за то, что уйдёт заказчику, отвечаете вы, а не история git.

14Обновление

Скилл, установленный через git clone, обновляется одной командой:

bun ~/.claude/skills/redmine-time/scripts/update.ts            # что нового
bun ~/.claude/skills/redmine-time/scripts/update.ts --apply    # обновиться

Если вы правили файлы скилла у себя, обновление не применится и скажет об этом — ваши изменения не затираются.

Чтобы скилл обновлялся сам — раз в сутки при запуске Claude Code, — добавьте в ~/.claude/settings.json hook. Без него обновление только ручное.

{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup",
        "hooks": [
          {
            "type": "command",
            "command": "bun \"$HOME/.claude/skills/redmine-time/scripts/update.ts\" --apply --quiet --if-stale 86400",
            "timeout": 30
          }
        ]
      }
    ]
  }
}

На Windows вместо $HOME укажите $USERPROFILE. Если раздел hooks в файле уже есть, добавьте запись в него, а не второй раздел. Проверка выполняется не чаще раза в сутки и молчит, когда обновлений нет.

16Что скилл не делает

  • Не списывает часы за других сотрудников — только за владельца ключа.
  • Не расширяет ваши права: создать или закрыть проект, добавить участника, назначить роль или править wiki можно только в пределах прав вашей учётной записи, а архивирует проекты только администратор Redmine.
  • Не связывает задачи разных инстансов: между ними возможна только перекрёстная ссылка в тексте.
  • Не списывает время сам: оценка по истории git — черновик, часы подтверждаете вы.
  • Не знает о том, что вы прочитали задачу в браузере: отметку «просмотрено» для сводки новых событий ставит команда с флагом --mark.
  • Не требует плагинов Redmine — работает на штатном REST API версий 5.x и 6.x.
