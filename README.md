# redmine-time

Скилл для [Claude Code](https://claude.com/claude-code): учёт трудозатрат и работа с задачами Redmine прямо из чата — на естественном языке, без открытия браузера.

```
Вы:     потратил 2 часа на #1234, писал протокол обмена
Claude: Записать в Redmine (ru)?
        2026-09-22 · #1234 · 2.00ч · Программирование
        «Реализация протокола обмена»
Вы:     да
Claude: Записано. Итого сегодня 6.5ч из 8.
```

```
Вы:     что у меня нового и какие сроки горят?
Claude: Новое с прошлой проверки:
        #25127 — 2 комментария от Светланы, ждёт ответа
        #25140 — назначена на вас сегодня, срок 25.09
        Просрочено: 3 задачи, ближайший срок — сегодня (#197).
```

## Как устроено

```
чат Claude Code  →  SKILL.md (правила)  →  scripts/redmine.ts  →  Redmine REST API
```

Скилл — это инструкции для модели плюс CLI на [Bun](https://bun.sh) и TypeScript: нулевые зависимости, нативный `fetch`, строгая типизация (`strict` + `noUncheckedIndexedAccess`). CLI можно использовать и отдельно от Claude — как обычную утилиту командной строки.

Поддерживается несколько инстансов Redmine одновременно: сводки «что нового» и «сроки» собираются сразу по всем.

## Возможности

| Область | Что умеет |
|---|---|
| Трудозатраты | списать часы на задачу или проект, пачкой за несколько дней, поправить и удалить запись |
| Отчёты | сколько списано за период в разрезе задач, дней, проектов, видов деятельности; дни с недобором до нормы |
| Входящие | новые задачи на вас, назначения, чужие комментарии и изменения полей — с отметкой «просмотрено» |
| Сроки | просроченное, сегодняшнее и ближайший горизонт с оценкой, списанным и % готовности |
| Задачи | карточка с историей, поиск, фильтры, создание задачи, комментарии, смена статуса и готовности |
| Аналитик | описание задачи и комментарий пишутся по редакционному стандарту: результат, объём, критерии приёмки, явные связи и запрос к адресату с датой |
| Декомпозиция | крупная работа разбирается на дерево подзадач с шапкой-обзором; агрегаты оценок, списаний и готовности считаются по дереву |
| Проверка перед отправкой | каждый уходящий текст сканируется на секреты, платёжные и персональные данные, внутренние адреса, самооговор, обещания без условий |
| Подтверждение | ни одна запись не уходит без предпросмотра: команда без `--yes` показывает точный текст и выходит |
| Сбор по git | коммиты за период превращаются в черновик: куда списать часы и какие задачи завести на сделанное для клиента |
| Автообновление | скилл сам подтягивает обновления раз в сутки, не затирая локальные правки |

## Установка

Нужны [Claude Code](https://claude.com/claude-code) и [Bun](https://bun.sh) ≥ 1.2.

```bash
git clone https://github.com/33solutions/redmine-time.git ~/.claude/skills/redmine-time
```

Скилл подхватывается автоматически при следующем запуске Claude Code. Для установки только в один проект клонируйте в `<проект>/.claude/skills/redmine-time`.

## Настройка

```bash
mkdir -p ~/.redmine
cp ~/.claude/skills/redmine-time/config.example.json ~/.redmine/config.json
```

Впишите URL и API-ключ. Ключ берётся в Redmine: **Моя учётная запись → Ключ доступа к API → Показать**. Если блока нет — администратор не включил REST API (*Администрирование → Настройки → API*).

```json
{
  "default": "work",
  "instances": {
    "work": {
      "url": "https://redmine.example.com/",
      "apiKey": "…",
      "defaultActivity": "Разработка",
      "dailyTargetHours": 8,
      "projectAliases": { "ядро": "core-platform" }
    }
  }
}
```

| Поле | Назначение |
|---|---|
| `defaultActivity` | вид деятельности по умолчанию при списании часов |
| `dailyTargetHours` | дневная норма для отчёта о недоборе |
| `projectAliases` | короткие имена проектов для себя: `"ядро" → "core-platform"` |

Переменные окружения `REDMINE_URL`, `REDMINE_API_KEY`, `REDMINE_INSTANCE` переопределяют конфиг — удобно для CI.

Проверка:

```bash
bun ~/.claude/skills/redmine-time/scripts/redmine.ts whoami
```

## Как просить Claude

Обычные фразы, номер задачи — с решёткой:

- «спиши 3 часа на #1234, рефакторинг ядра»
- «отрази вчерашний день: 4 часа на #1234 и 2 на #1250»
- «сколько я списал на этой неделе?»
- «где у меня недобор часов за сентябрь?»
- «что нового по моим задачам?»
- «какие сроки горят?»
- «покажи #1234 с последними комментариями»
- «поставь #1234 в работу, 60% готовности»

Перед любой записью Claude показывает, что именно уйдёт в Redmine, и ждёт подтверждения.

## CLI

Полный список: `bun scripts/redmine.ts help`.

```bash
R=~/.claude/skills/redmine-time/scripts/redmine.ts

# трудозатраты
bun $R log --issue 1234 --hours 2.5 --comment "Рефакторинг ядра"
bun $R log --issue 1234 --hours 1h30 --date yesterday --activity "Анализ" --dry-run
bun $R batch --file entries.json          # пачкой из JSON
bun $R entries --period week --group issue
bun $R gaps --period month --target 8

# входящие и сроки
bun $R inbox --all-instances --since -3
bun $R inbox --all-instances --mark
bun $R due --all-instances --days 14

# задачи
bun $R issue 1234 --comments 5
bun $R issues --mine --limit 20
bun $R create-issue --project core --subject "Тема" --description-file d.html --due +7   # предпросмотр
bun $R create-issue --project core --subject "Тема" --description-file d.html --yes      # создание
bun $R comment 1234 --text-file c.html --yes
bun $R update-issue 1234 --status "В работе" --done 60 --yes

# дерево подзадач
bun $R create-tree --file plan.json          # предпросмотр родителя и всех подзадач
bun $R create-tree --file plan.json --yes
bun $R tree 1234                             # агрегаты оценок, списаний, готовности

# проверка текста и разметка инстанса
bun $R scan --file draft.html
bun $R detect-markup --project core

# сделанное по истории git
bun $R repos add --path . --instance work --project core --client "Клиент" --activity "Программирование"
bun $R harvest --repo . --period week --out /tmp/harvest
```

## Сбор сделанного по git

Репозитории привязываются к проектам Redmine, и работа за период собирается из истории:

```bash
bun $R repos list
bun $R harvest --period last-week --out /tmp/harvest
```

Коммиты группируются в рабочие сессии (разрыв больше `--gap` минут — новый заход), часы считаются по времени сессии плюс разогрев `--warmup`. Коммиты с `#NNNN` относятся к существующей задаче — она проверяется в Redmine; остальные группируются по теме, и по каждой предлагается новая задача с черновиком описания. `--out` сохраняет `entries.json` для `batch`, `plan.json` и описания.

Оценка часов — **черновик по времени коммитов**, а не факт: её проверяет человек, прежде чем что-то отправлять.

## Обновление

Скилл обновляет себя сам, если установлен через `git clone`:

```bash
bun ~/.claude/skills/redmine-time/scripts/update.ts            # посмотреть, что нового
bun ~/.claude/skills/redmine-time/scripts/update.ts --apply    # обновиться
```

Обновление применяется только перемоткой вперёд и только при чистом рабочем дереве — локальные правки не затираются. Чтобы обновление происходило само, добавьте в `~/.claude/settings.json` hook:

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup",
        "hooks": [
          {
            "type": "command",
            "command": "bun \"$HOME/.claude/skills/redmine-time/scripts/update.ts\" --apply --quiet --if-stale 86400",
            "timeout": 30
          }
        ]
      }
    ]
  }
}
```

На Windows вместо `$HOME` используйте `$USERPROFILE`. Проверка выполняется не чаще раза в сутки и молчит, когда обновлений нет.

## Разработка и релизы

```bash
bun scripts/selftest.ts          # 69 проверок разбора ввода, правил и сбора по git — без обращения к Redmine
bun scripts/audit-repo.ts --history   # тот же сканер по файлам репозитория и всей истории
bunx tsc --noEmit
```

CI прогоняет всё это на каждый push и pull request. Релиз выпускается сам: достаточно изменить `VERSION` в `main` — GitHub Actions проверит код, соберёт архив и PDF инструкции, создаст тег и запись в Releases с заметками из `CHANGELOG.md`.

Форматы ввода: часы — `2`, `2.5`, `1h30`, `1:30`, `90m`; даты — `2026-09-22`, `22.09`, `today`, `yesterday`, `-3`, `+7`; периоды — `week`, `last-week`, `month`, `last-month`, `2026-09`, `2026-09-01..2026-09-15`.

Флаг `--json` даёт машиночитаемый вывод, `--dry-run` — предпросмотр без записи, `--instance <имя>` выбирает Redmine, `--all-instances` собирает сводку по всем.

## Безопасность

**Подтверждение.** Запись в Redmine требует явного `--yes`. Без него `log`, `batch`, `comment`, `create-issue`, `create-tree`, `update-issue`, `edit` печатают полный предпросмотр — ровно тот текст, который уйдёт, — и завершаются. Это свойство инструмента, а не договорённость с моделью.

**Проверка содержимого.** Перед отправкой каждый текст проходит `scripts/guard.ts`:

- *запрет* — пароли и ключи, токены (`ghp_…`, `sk-…`, JWT, `Bearer …`), приватные ключи, строки подключения с учётными данными, номера карт (проверка по Луну), СНИЛС и паспортные данные;
- *запрет в клиентских задачах, предупреждение во внутренних* — внутренние IP и имена узлов, самооговор, оценки людей, обещания без условий, внутренняя экономика, упоминание других заказчиков;
- *предупреждение* — локальные пути, телефоны, адреса почты, ИНН.

Аудитория переключается флагом `--audience internal`. Запрет снимается только явным `--override-guard` — и об этом сообщается в выводе. Проверить текст отдельно: `scan --file draft.html` (код возврата `2`, если отправлять нельзя).

**Ключи.** API-ключ хранится только локально в `~/.redmine/config.json`, не печатается в вывод и исключён из репозитория через `.gitignore`. Ключ даёт ровно те права, что есть у его владельца: чужие проекты и чужие списания остаются недоступны.

## Файлы

| Путь | Назначение |
|---|---|
| `SKILL.md` | инструкции для модели: роль аналитика, протокол подтверждения, сценарии, диагностика |
| `scripts/redmine.ts` | CLI: команды работы с задачами, временем, деревьями и сводками |
| `scripts/guard.ts` | проверка уходящих текстов на компрометацию |
| `references/editorial.md` | редакционный стандарт: шаблоны описаний, комментариев, правила декомпозиции |
| `references/safety.md` | что нельзя отправлять и как переформулировать |
| `references/api.md` | особенности Redmine REST и подводные камни |
| `docs/instruction.pdf` | инструкция для сотрудников |
| `config.example.json` | образец конфига |

Состояние в домашнем каталоге: `~/.redmine/config.json` (профили), `cache.json` (справочники, TTL сутки), `state.json` (отметка «просмотрено» для `inbox`).

## Разработка

```bash
bun scripts/redmine.ts help
bun add -d typescript bun-types && ./node_modules/.bin/tsc --noEmit
```

Проверено на Redmine 5.x и 6.x. Совместимость: команды используют только штатный REST API без плагинов.
